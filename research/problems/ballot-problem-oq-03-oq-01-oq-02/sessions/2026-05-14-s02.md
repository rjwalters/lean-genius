## §2  Cluster F (lines 2370, 2386) — PR #19005's fix recommendation is wrong; corrected 1-line replacement

### §2.1  Original code (BallotProblemOQ03OQ02.lean:2369-2372 and 2385-2388)

```lean
have hkj_drop : ((t.2 cj).val.take kj).drop kj = [] := by
  nth_rw 2 [← List.length_take_of_le hkj_le]; exact List.drop_length
rw [List.drop_append, List.length_take_of_le hkj_le, Nat.sub_self,
    List.drop_zero, hkj_drop, List.nil_append]
```

(line 2385-2388 is the symmetric pattern with `ki`/`ci` in place of `kj`/`cj`)

### §2.2  Build-log error (verbatim from log line 820-825)

```
error: Proofs/BallotProblemOQ03OQ02.lean:2370:54: Type mismatch
  List.drop_length
has type
  List.drop (List.length ?m.461) ?m.461 = []
but is expected to have type
  List.drop kj (List.take (List.take kj ↑(t.snd cj)).length ↑(t.snd cj)) = []
```

Symmetric error at line 2386:56.

**Root-cause confirmation**: `nth_rw 2 [← List.length_take_of_le hkj_le]`
fires in the WRONG position at v4.26.0.  It rewrote the *inner* `kj`
(the argument of the inner `take`) instead of the *outer* `kj` (the
argument of the outer `drop`).  Confirmed by goal shape: inner take
now has `(List.take kj ↑(t.snd cj)).length` as its first argument
instead of `kj`, and the outer `drop kj` is unchanged.  After the
rewrite, `List.drop_length`'s pattern `L.drop L.length = []` cannot
unify (the inner-take's outer wrapping makes `L = (take ((take kj _).length) _)` while the drop arg is plain `kj`).

PR #19005's "occurrence renumbering for nested `.take`/`.drop`
patterns" hypothesis is correct in spirit.

### §2.3  PR #19005's proposed fix — INCORRECT

> **F**: replace `nth_rw 2 [← List.length_take_of_le hkj_le]` with
> `have h : (L.take k).length = k := List.length_take_of_le _; rw [← h, List.drop_length]`.

This **does not work** because `rw [← h]` rewrites *every* occurrence
of `k` in the LHS of the form `(L.take k).length = k`:

- Pre-rewrite goal: `((t.2 cj).val.take kj).drop kj = []`
- After `rw [← h]` with `h : (L.take kj).length = kj`, Lean rewrites
  **both** `kj` occurrences to `((t.2 cj).val.take kj).length`, giving:
  `((t.2 cj).val.take (((t.2 cj).val.take kj).length)).drop (((t.2 cj).val.take kj).length) = []`
- Now `List.drop_length`'s `L.drop L.length = []` pattern unifies
  only if the take's first argument equals the drop's argument.
  Here `take` arg = `((take kj _).length)` ≠ `(take ((take kj _).length) _).length` (different `.length`).
  **Same Type mismatch class as the original `nth_rw 2` failure.**

PR #19005's mathlibGap note "F | `nth_rw N` occurrence renumbering"
is correct, but the proposed alternative shares the same failure mode.

### §2.4  Corrected fix — Option A (RECOMMENDED, 1 line)

```lean
have hkj_drop : ((t.2 cj).val.take kj).drop kj = [] :=
  List.drop_of_length_le (List.length_take_of_le hkj_le).le
```

Mechanism (each step pin-verified at SHA `2df2f015…` in §1):
1. `List.length_take_of_le hkj_le : ((t.2 cj).val.take kj).length = kj`
2. `.le : ((t.2 cj).val.take kj).length ≤ kj` (via Mathlib `Eq.le` alias for `le_of_eq`)
3. `List.drop_of_length_le : L.length ≤ i → L.drop i = []`
4. Application with `L := (t.2 cj).val.take kj`, `i := kj` closes the goal.

Symmetric fix for line 2386:

```lean
have hki_drop : ((t.2 ci).val.take ki).drop ki = [] :=
  List.drop_of_length_le (List.length_take_of_le hki_le).le
```

**LOC delta**: 2 lines (the original `have ... := by\n  nth_rw 2 [...]; exact ...`) → 2 lines (one-liner per site).  Net: 0 LOC.  Robustness: no fragile `nth_rw` pattern, no tactic-state dependency on rewrite-engine occurrence numbering.

### §2.5  Corrected fix — Option B (slightly more verbose, no `Eq.le`)

If Mathlib's `Eq.le` alias hasn't propagated to the parent file's
imports (it lives in `Mathlib.Order.Basic` which is imported
transitively, but a paranoid reviewer may prefer explicit):

```lean
have hkj_drop : ((t.2 cj).val.take kj).drop kj = [] :=
  List.drop_of_length_le (le_of_eq (List.length_take_of_le hkj_le))
```

Same length, same mechanism, uses the unaliased `le_of_eq` from
Mathlib `Order.Basic`.

### §2.6  Corrected fix — Option C (defensive, preserves the original idiom)

If the mechanic prefers to keep the `nth_rw`-style narrative for
readability, use `conv` to select the rewrite location:

```lean
have hkj_drop : ((t.2 cj).val.take kj).drop kj = [] := by
  conv_lhs => rw [show kj = ((t.2 cj).val.take kj).length from
                    (List.length_take_of_le hkj_le).symm]
  -- but only the LAST `kj` in the expression; would need further
  -- conv navigation: `conv_lhs => arg 2`  to target the drop-arg

```

Option C is brittle and not recommended — it has the same

### §4.1  Build-log error (line 2249:19 verbatim, abbreviated)

```
error: Proofs/BallotProblemOQ03OQ02.lean:2249:19: Tactic `rewrite` failed: Did not find an occurrence of the pattern
  colEntry (↑(t'.snd ci)) c₀
in the target expression
```

Hypothesis context shows `ci : Fin r := canonI cfg hwf t ht` (a
`let`-binding) and `c₀ : ℕ := canonCol cfg hwf t ht`.  In v4.26.0
the elaborator has *unfolded* `ci` and `c₀` to their canonical-form
underlying terms (`⟨N / r % r, hiv⟩` and `N / (yBound cfg * (r * r))`),
breaking the `rw [...]` literal-pattern match.

### §4.2  PR #19005's recommendation analysis

> **D**: `set ci := canonI cfg hwf t ht with hci_def` before each `rw`, OR explicit `conv_lhs => rw [show … from …]`.

The `set ... with hci_def` recommendation **will not help** —
the local `let`-binding `ci := canonI cfg hwf t ht` is already
present in the proof state (visible at line 2294 of the source
or thereabouts; appears in the build-log hypothesis list).  The
issue is that the *goal* has been zeta-reduced past the
`let`-binding by the time `rw` runs.  Switching `have`/`let` to
`set` does not prevent this reduction.

**Sharpening**: PR #19005's second option (`conv_lhs => rw [show … from …]`)
is the right path, but needs the explicit `colEntry`-term-shape
witness, e.g.:

```lean
-- Original (line 2249):
rw [colEntry_eq_ci c₀ (le_refl _)] at ...

-- Corrected:
have hzeta_ci : (canonI cfg hwf t ht) = ⟨N / r % r, hiv⟩ := rfl  -- or relevant zeta witness
rw [colEntry_eq_ci c₀ (le_refl _), hzeta_ci.symm] at ...
```

(Alternative: rewrite the *hypothesis* `colEntry_eq_ci` to match
the zeta-reduced goal form: `colEntry (↑(t'.snd ⟨N / r % r, hiv⟩)) c₀ = colEntry (↑(t.snd ⟨N / r % r, hiv⟩)) c₀`.)

**Best-case mechanic recipe** — let the rewrite engine handle the
zeta itself via `simp only`:

```lean
-- Replace `rw [colEntry_eq_ci ...] at h` with:
simp only [show canonI cfg hwf t ht = ⟨N / r % r, hiv⟩ from rfl,
           colEntry_eq_ci c₀ (le_refl _)] at h
```

(The `show ... from rfl` provides the zeta-equality as a simp arg.)

**LOC delta**: +1-2 lines per of 6 rw-sites = ~6-12 LOC for full
Cluster D resolution.  PR #19005 estimated ~30 LOC; sharper

intent — `simp only [hN]` succeeds where `congr 1; exact hN` fails

sees no goals.

**Sharpening**: PR #19005's "replace `rw [hN]` with `simp only [hN]`"

The mechanic action is otherwise unchanged.

is correct.  The current `simp [splitPosAt, hci', hc₀', hy₀']` leaves
an arithmetic residual `c₀ + (y₀ - cfg.sources ci) = ki` (visible in
build log line 2336 hypothesis trace) which `omega` will close.

**LOC delta**: 4 sites replace `congr 1; exact hN` (12 chars of tactic

~4 chars added per site.  Plus `; omega` appended at lines 2336/2338

  (PR #19005's recommendation) fails for the same root cause as the
  original `nth_rw 2` — `rw [← h]` rewrites every occurrence.  Always
  use `drop_of_length_le ... .le` for "drop kj of (take kj L)" patterns
  rather than building from `length_take_of_le` + `drop_length`.
- **A.trap.1**: At v4.26.0, `↑(cast ⋯ e)` does **not** unfold to
  `(cast ⋯ e).val` for `Subtype.val`-style coercions.  Always declare
  both `.val` and coercion forms of `cast_*_val` lemmas when the
  underlying type is `Subtype`-backed (here `PathMN`).
- **D.trap.1**: `set foo := <complex-term>` does NOT prevent zeta
  reduction of `foo` in the goal at v4.26.0 — only the local
  binding remains.  Use `show <zeta-reduced form>` or `simp only [show foo = … from rfl, ...]` to bridge.
- **E.trap.1**: `congr 1; exact hN` is fragile when the residual goal
  after `congr 1` is not literally `hN`'s shape — `congr` may go too
  deep or stop too early.  Prefer `simp only [hN]` for whole-term
  equality hypotheses.
- **F.trap.2**: `nth_rw N` occurrence indexing at v4.26.0 changed for
  nested `take`/`drop` patterns — `nth_rw 2 [← List.length_take_of_le _]`
  on `((L.take k).drop k = [])` now fires the inner occurrence instead
  of the outer.  When in doubt, refactor to avoid `nth_rw` entirely
  (use direct lemma application via `drop_of_length_le`).
