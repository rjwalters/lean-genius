## Structural diagnosis: the double-vanishing case

The S67 prediction failed on `(3,2,2)` because S67 implicitly
assumed every c'-column cell `(i, c'.2)` with `i < c'.1` is a
non-vanishing crossing.  In `(3,2,2)`, the cell `(1,1)` with
`i = 1 < c'.1 = 2` is a **double-vanishing crossing**:

* `(1,1)` in `μ`: not a corner (has leg `(2,1) ∈ μ`), but its
  only strict-hook descendant is the corner `(2,1) ≠ c`.
  So `gnwProb μ c K (1,1) = (1/1) · gnwProb (K−1) (2,1) = 0`.

* `(1,1)` in `μ\c' = (3,2,1)`: IS a corner (right `(1,2) ∉`,
  below `(2,1) ∉` after `c'`-removal).  `(1,1) ≠ c`, so
  `gnwProb (μ\c') c K (1,1) = 0`.

**General double-vanishing condition.**  Cell `(i, c'.2)` with
`i < c'.1` is double-vanishing iff `i = c'.1 − 1` AND
row `i` length in `μ` equals `c'.2 + 1`.  Proof sketch:

* If `i ≤ c'.1 − 2`: below neighbor `(i+1, c'.2) ∈ μ\c'`
  (column `c'.2` retains height `c'.1` cells in μ\c'), so
  `(i, c'.2)` has non-empty leg in `μ\c'`, hence not a
  corner of `μ\c'`.  Non-vanishing crossing.

* If `i = c'.1 − 1`: below neighbor `(c'.1, c'.2) = c' ∉ μ\c'`.
  Right neighbor `(i, c'.2 + 1) ∈ μ\c'` iff row `i` length
  > `c'.2 + 1` in `μ\c'` = same as in `μ`.  If row `i` length =
  `c'.2 + 1`, both neighbors are absent, `(i, c'.2)` is a corner
  of `μ\c'`, double-vanishing.

In `(3,2,2)`: `c'.1 − 1 = 1`, row `1` length = 2 = `c'.2 + 1`.
✓ matches.  In `(3,2)`, `(3,2,1)`, `(4,2)`, `(4,3)`:
`c'.1 − 1 = 0`, row `0` length is `3` or `4`, strictly greater
than `c'.2 + 1`.  No double-vanishing crossing.

**Implication for S57.7.**  The non-vanishing c'-column
crossings in case 1 are cells `(i, c'.2)` with
`i < c'.1 ∧ row i length > c'.2 + 1` (and `(i, c'.2) ∈ μ\c'`).
S57.6 prep 1's `strictHookCells_off_spine_class_at_c'`
partition currently classifies all of `{i < c'.1}` as "arm-class
crossing"; a refinement is needed to distinguish non-vanishing
from double-vanishing (or, equivalently, S57.7's per-cell
residual identity must treat the double-vanishing cells as
contributing 0 on both sides, which is automatic).

## Implication for `F_side_identity_aligned`'s proof

The S57.7 plan (state.md lines 695–727) reads:

> 2. **Sub-lemma S57.7-col — c'-column residual formula.** […]
>    **Conjecture:** c'-column residual = `−(h_d − 2) ·
>    |{i < c'.1 : (i,c'.2) ∈ μ\c'}|` — to be tested on `(3,2,2)`
>    and `(4,3)` in S68 analysis.

S68 refutes both `−(h_d − 2)` per-crossing scaling and the
`|{i < c'.1 : (i,c'.2) ∈ μ\c'}|` crossing count interpretation.
The correct framing:

```
c'-column residual = − |{(i,j) ∈ μ\c' : i < c'.1 ∧ j > c'.2}|
                   = − (number of off-spine c-arm cells)
```

For `c.1 = 0` (all test diagrams), this equals `c.2 − c'.2`.

**Per-crossing residual.**  Of the cells `{i < c'.1 :
(i, c'.2) ∈ μ\c'}`, the non-vanishing ones share the total
`−|off-spine c-arm region|`.  Concretely, in all five tests
exactly one cell carries the full residual `−|c-arm|` and any
others (when `c'.1 ≥ 3` or row-length conditions hold) are
double-vanishing.  Whether the residual is always concentrated
on a single cell, or can spread across multiple non-vanishing
crossings, is the recommended Session 69 follow-up.

## Suggested Session 69 — multi-crossing concentration test

Compute the c'-column residual on a diagram with **multiple
non-vanishing c'-column crossings** in case 1 to test whether
the per-crossing residual is concentrated on a single cell or
distributed.  Candidate: `μ = (4,3,2,1)` with `c = (0,3)`,
`c' = (3,0)` — but `c.1 = 0 < 3 = c'.1`, `c.2 = 3 > 0 = c'.2`
(case 1), and `c'.1 − 1 = 2 ≥ 1` with multiple candidate
crossings `(0, 0), (1, 0), (2, 0)`.  However, several of these
may be off-spine (since `c'.2 = 0`, "off-spine of c'-column"
becomes degenerate); a better test is `μ = (4,3,3)` with
`c = (0,3)` and `c' = (2,2)`, giving candidate crossings
`(0, 2)` and `(1, 2)` both in row-length > 3 territory.
Alternatively, the simpler `μ = (5,3,2)` with `c = (0,4)`,
`c' = (2,1)` gives two non-vanishing arm-class crossings
`(0, 1)` and `(1, 1)` both with row lengths exceeding `c'.2 + 1`.

The "single-cell concentration" or "distributed residual"
behavior here will tell us whether S57.7's c'-column sub-lemma
needs only one cell's residual computed, or a sum.
