## 1. Purpose of this PREP

S1 OBSERVE (PR #18248, merged 2026-05-12T19:35:13Z) selected
**Noether's degree bound (1916)** as the S2 target and shortlisted a
five-step proof outline:

1. Orbit polynomial `P_v(T) = ∏_{w ∈ Orbit(v)} (T - w)` is `G`-invariant.
2. Each `v` is integral over `k[V]^G` of degree `≤ |G|`.
3. `k[V]` is integral over the sub-`k`-algebra generated by orbit-polynomial coefficients.
4. Atiyah–Macdonald 5.1 (integral + finite-type ⇒ module-finite) applies.
5. Module-finite implies finite generation of the bottom invariant ring.

The S1 state.md committed to an **S2 ACT scaffold** of
`proofs/Proofs/Hilbert14OQ04.lean` with bespoke `orbitPolynomial` /
`orbit_polynomial_invariant` / `orbit_polynomial_degree` / `vanishes_at_v`
lemmas, followed by a sorried `noether_degree_bound` theorem.

**Discovery (this PREP)**: A targeted Mathlib API audit shows that
**all four "bespoke" key lemmas are already proved in Mathlib** under a
slightly different (and strictly more general) API. The S2 ACT plan
should pivot from "scaffold from scratch" to "chain Mathlib pieces"
before any Lean code is written; doing so removes the typeclass-setup
fragility flagged in S1 state.md ("If the Mathlib API for `MvPolynomial`
proves too thin…") and shrinks the genuine new infrastructure to a
single connecting lemma.

This PREP records the audit and the revised S2a / S2b / S2c sub-step
plan. It does not edit `state.md`; the next S2 ACT session can promote
the plan into state.md and proceed to Lean coding.

## 2. Audit findings (Mathlib API)

### 2.1 The orbit polynomial: `prodXSubSMul` is already in Mathlib

**Location**: `Mathlib/Algebra/Polynomial/GroupRingAction.lean`, lines 82–104.

```lean
-- Mathlib (verbatim, line-stable as of 2026-05-13):
variable (G : Type*) [Group G] (R : Type*) [CommRing R]
  [MulSemiringAction G R] [Fintype G]

/-- the product of `(X - g • x)` over distinct `g • x`. -/
noncomputable def prodXSubSMul (x : R) : R[X] :=
  letI := Classical.decEq R
  (Finset.univ : Finset (G ⧸ MulAction.stabilizer G x)).prod fun g ↦
    Polynomial.X - Polynomial.C (ofQuotientStabilizer G x g)

theorem prodXSubSMul.monic (x : R) : (prodXSubSMul G R x).Monic := …
theorem prodXSubSMul.eval (x : R) : (prodXSubSMul G R x).eval x = 0 := …
theorem prodXSubSMul.smul (x : R) (g : G) :
    g • prodXSubSMul G R x = prodXSubSMul G R x := …
theorem prodXSubSMul.coeff (x : R) (g : G) (n : ℕ) :
    g • (prodXSubSMul G R x).coeff n = (prodXSubSMul G R x).coeff n := …
```

**Observations:**

- `prodXSubSMul G R x` quotients by the **stabilizer** of `x`, so its
  degree is exactly `|Orbit(x)| = |G / stab(x)| ≤ |G|`. The S1 plan's
  `orbit_polynomial_degree` ("`(orbitPolynomial v).natDegree ≤ |G|`")
  follows immediately from `Finset.card_univ` on the quotient.
- `prodXSubSMul.eval` discharges the S1 plan's `vanishes_at_v` exactly
  (`(orbitPolynomial v).eval v = 0`).
- `prodXSubSMul.coeff` discharges the S1 plan's
  `orbit_polynomial_invariant`: each coefficient is fixed by every
  `g ∈ G`. The relevant `Subalgebra` membership ("each coefficient
  lies in `MulAction.fixedPoints G R`") is then a direct unfold.
- `prodXSubSMul.smul` gives the corresponding `Polynomial`-level
  invariance, useful for stating the orbit polynomial as a polynomial
  over the **invariant subring**, not just over `R`.

**Setup mismatch (real but small):** Mathlib's `prodXSubSMul` uses
`[MulSemiringAction G R]` (= `DistribMulAction` + `MulDistribMulAction`).
The OQ-01 file `proofs/Proofs/Hilbert14NonReductive.lean` already uses
the same pair of typeclasses (`[DistribMulAction G R]` +
`[MulDistribMulAction G R]`, lines 142–143), so no new typeclass
overhead is needed in the OQ-04 file.

### 2.2 The invariant subalgebra: `FixedPoints.subalgebra` is in Mathlib

**Location**: `Mathlib/Algebra/Algebra/Subalgebra/Operations.lean`,
lines 83–104.

```lean
variable (G : Type*) [Monoid G] [MulSemiringAction G B]
  [SMulCommClass G A B]

def FixedPoints.subsemiring : Subsemiring B' where …
def FixedPoints.subring : Subring B where …
def FixedPoints.subalgebra : Subalgebra A B' where
  __ := FixedPoints.subsemiring B' G
  ...
```

This is **the** API for the invariant ring as an `A`-subalgebra of `B`,
parameterized by the base ring `A` (= `k`) and the action target `B` (=
`MvPolynomial (Fin n) k`).

**Pivot**: the S1 state.md's tentative `noether_degree_bound`
statement —

```lean
(MulAction.fixedPoints G (MvPolynomial (Fin n) k) :
    Subalgebra k (MvPolynomial (Fin n) k)) = …
```

— should be rewritten as

```lean
FixedPoints.subalgebra k (MvPolynomial (Fin n) k) G = …
```

The `MulAction.fixedPoints`-as-`Subalgebra` ascription is not a standard
Mathlib coercion; `FixedPoints.subalgebra` is the canonical bearer.

### 2.3 The symmetric-group case = fundamental theorem of symmetric polynomials

**Location**: `Mathlib/RingTheory/MvPolynomial/Symmetric/FundamentalTheorem.lean`,
line 293.

```lean
lemma esymmAlgHom_fin_bijective (n : ℕ) :
    Function.Bijective (esymmAlgHom (Fin n) R n)
```

with `esymmAlgHom σ R n : MvPolynomial (Fin n) R →ₐ[R] symmetricSubalgebra σ R`
defined at line 134, sending `X_i ↦ e_{i+1}` (the `(i+1)`-st elementary
symmetric polynomial).

**Consequence (literal Noether for `S_n`):** When `G = Equiv.Perm (Fin n)`
acts on `MvPolynomial (Fin n) k` by the canonical `rename`-style action,
the invariant ring `MvPolynomial^G ≅ symmetricSubalgebra (Fin n) k` is
generated, as a `k`-algebra, by `e_1, …, e_n`, each of total degree
`≤ n`. Since `|G| = n!`, the Noether bound `deg ≤ |G| = n!` is satisfied
with **enormous slack**: the bound is actually `deg ≤ n ≤ n!` for the
symmetric group.

This realises the OQ-04 S2 target **as a direct corollary of an
existing Mathlib theorem** for the most pedagogically natural finite
group (the symmetric group). The S2a sub-step below converts this
observation into a one-screen Lean lemma.

### 2.4 Atiyah–Macdonald 5.1 is in Mathlib

**Location**: `Mathlib/RingTheory/IntegralClosure/IsIntegralClosure/Basic.lean`,
line 96.

```lean
theorem Algebra.IsIntegral.finite [Algebra.IsIntegral R A]
    [h' : Algebra.FiniteType R A] : Module.Finite R A

theorem Algebra.finite_iff_isIntegral_and_finiteType :
    Module.Finite R A ↔ Algebra.IsIntegral R A ∧ Algebra.FiniteType R A
```

This is the exact Atiyah–Macdonald 5.1 the S1 outline invokes in
step (4). **No bespoke `IntegralExtensionFinite` lemma is needed.**

### 2.5 The genuine gap: lifting a linear `G`-action on `k^n` to
`MulSemiringAction G (MvPolynomial (Fin n) k)`

**Status**: not built in Mathlib in a form directly usable by the S2 plan.

For the **permutation** sub-case (`G ≤ Equiv.Perm (Fin n)` acting by
`rename`), the necessary `MulSemiringAction` exists via `MvPolynomial.rename`
(`Mathlib/Algebra/MvPolynomial/Rename.lean`) — and this is exactly what
`symmetricSubalgebra` is the invariant ring of.

For the **general linear** sub-case (`G → GL_n(k)` acting on the
indeterminates by linear substitution), the standard lift would be:
build an `AlgHom (MvPolynomial (Fin n) k) (MvPolynomial (Fin n) k)`
from `linearMap → algHom` via `MvPolynomial.aeval` of `Fin n → R`-valued
data, then bundle that homomorphism action into `MulSemiringAction`.
This bundling is mechanical but not present in Mathlib.

**Scoping decision for S2 ACT**: stay in the **permutation** sub-case for
S2; the linear-substitution case is deferred to S3+. The permutation
sub-case is already where the Noether bound has the cleanest historical
proof (Galois 1846, Newton's identities), and where Mathlib gives the
result almost free.

## 3. Revised S2 ACT plan (5 sub-steps, all ≤ 50-line Lean)

**Bottom line**: The audit replaces the original "scaffold four lemmas +
sorry the main theorem" plan with a "chain Mathlib pieces, no `sorry`s
in the bounded case" plan. Build risk drops sharply because no new
typeclass machinery is introduced; all instances pre-exist in Mathlib.

### S2a — Noether bound for `Equiv.Perm (Fin n)` via fundamental theorem

**Statement (target Lean lemma):**

```lean
theorem noether_bound_symmetric_group {k : Type*} [CommRing k]
    {n : ℕ} (f : MvPolynomial (Fin n) k) (hf : f.IsSymmetric) :
    f ∈ Algebra.adjoin k
      (Set.image (esymm (Fin n) k ·) (Set.Iic n))
```

i.e. every symmetric polynomial lies in the subalgebra generated by
`e_1, …, e_n`. Bounds on total degree of the `e_i` follow from
`MvPolynomial.totalDegree_esymm` (already in Mathlib).

**Proof sketch** (≤ 15 lines): Use `esymmAlgHom_fin_bijective` to obtain
a preimage `p ∈ MvPolynomial (Fin n) k` of `⟨f, hf⟩`. Then `f` equals
`aeval (esymm σ R ·) p` (by `esymmAlgHom_apply`), and the image of
`aeval` lies in `Algebra.adjoin k (Set.range (esymm (Fin n) k))`, hence
in the `Iic n`-restricted adjoin by support analysis of `p`.

### S2b — Stabilizer-orbit-polynomial integrality, finite-group case

**Statement (target Lean lemma):**

```lean
theorem isIntegral_of_finite_action {G k R : Type*}
    [Group G] [Fintype G] [Field k] [CommRing R] [Algebra k R]
    [MulSemiringAction G R] [SMulCommClass G k R]
    (r : R) :
    IsIntegral (FixedPoints.subalgebra k R G : Subalgebra k R) r
```

**Proof sketch** (≤ 20 lines): take `p := (prodXSubSMul G R r).toFreshSubring
(FixedPoints.subalgebra k R G)` via `prodXSubSMul.coeff` + the
`MulSemiringAction → FixedPoints.subalgebra` membership unfolding.
Apply `IsIntegral.mk_monic` with `prodXSubSMul.monic` and
`prodXSubSMul.eval`.

### S2c — `Algebra.IsIntegral` of the whole ring over its invariants

**Statement (target Lean lemma):**

```lean
instance algebraIsIntegral_fixedPoints {G k R : Type*}
    [Group G] [Fintype G] [Field k] [CommRing R] [Algebra k R]
    [MulSemiringAction G R] [SMulCommClass G k R] :
    Algebra.IsIntegral (FixedPoints.subalgebra k R G) R
```

**Proof sketch** (≤ 5 lines): existence of the `IsIntegral` element-wise
proof in S2b directly upgrades to `Algebra.IsIntegral` via the standard
`Algebra.IsIntegral.mk` / `Algebra.isIntegral_iff` API.

### S2d — Finite generation via Atiyah–Macdonald

**Statement (target Lean theorem):**

```lean
theorem hilbert_noether_finite_group {k : Type*} [Field k]
    {n : ℕ} (G : Type*) [Group G] [Fintype G]
    [MulSemiringAction G (MvPolynomial (Fin n) k)]
    [SMulCommClass G k (MvPolynomial (Fin n) k)] :
    Algebra.FiniteType k
      (FixedPoints.subalgebra k (MvPolynomial (Fin n) k) G)
```

**Proof sketch** (≤ 25 lines): `MvPolynomial (Fin n) k` is f.g. as a
`k`-algebra (Mathlib: `MvPolynomial.algebraTensorAlgebra_finiteType`-like
result; alternatively use `Algebra.FiniteType.mvPolynomial`). Combine
with S2c via `Algebra.IsIntegral.finite` to get
`Module.Finite (FixedPoints.subalgebra …) (MvPolynomial (Fin n) k)`.
Apply the **Noetherian step**: a sub-`k`-algebra `A ⊆ B` with
`B` `k`-f.t. and `B` `A`-f.g.-as-module forces `A` `k`-f.t. (standard;
Mathlib: `Subalgebra.fg_of_finite` / `Module.Finite.trans` machinery).

## 5. Anti-targets (what NOT to do in S2 ACT)

1. **Do NOT rebuild `prodXSubSMul`.** The bespoke `orbitPolynomial` in
   the S1 plan is a verbatim duplicate of Mathlib's existing API.
   Anyone proposing a fresh definition should be redirected here.
2. **Do NOT scaffold a fresh `ReynoldsOperator` for OQ-04.** The OQ-01
   file `proofs/Proofs/Hilbert14NonReductive.lean` already has
   `reynoldsSum` + 7 averaging facts and uses the same `[DistribMulAction
   G R] + [MulDistribMulAction G R]` typeclass pair as `prodXSubSMul`.
   Cross-import OQ-01's namespace as in the S1 plan's step 5.
3. **Do NOT chase the linear-substitution lift in S2.** The
   `MulAction G (Fin n) → MulSemiringAction G (MvPolynomial (Fin n) k)`
   bundling is a real Mathlib gap (§2.5) but it's the wrong S2 battle —
   it adds typeclass overhead orthogonal to the Noether-bound content.
   Defer to S3.
4. **Do NOT introduce `IsLocallyNilpotent`.** That is the alternate S2
   entry point in S1 state.md ("Alternative S2 entry point"); given the
   Mathlib audit, the orbit-polynomial route is now strictly preferable
   (no new typeclass), so the LND axis should remain S5+ as stated in
   `problem.md` §"Tier-2 / Tier-3".
5. **Do NOT touch `meta.json`, `problem.md`, `knowledge.md`, or
   `state.md` in this PREP's PR.** The audit is a forward-design
   memo; promotion of these findings into `state.md` happens in the S2
   ACT session, not now.

ordering that minimises typeclass-elaboration risk is:
