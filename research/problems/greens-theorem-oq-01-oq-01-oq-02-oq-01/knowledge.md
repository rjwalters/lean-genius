### Five insights

1. **The "4-case sign analysis" in the parent is exponential in n.**
   The parent handles 2² = 4 orderings of `(a≤b ∨ b<a, c≤d ∨ d<c)`.
   A direct n-dim port would do `2^n`. Mitigation: prove the
   `uIcc`-symmetric statement directly (using
   `Set.uIoc = uIoc` integrability) and recover the standard form
   for any ordering at extraction time. The single
   `uIcc`-form proof should be ~80 lines once written.

2. **Adjacent transpositions are the right algebraic basis.**
   `Equiv.Perm (Fin n)` is generated by `Equiv.swap i.castSucc i.succ`
   for `i : Fin n` (this is the standard "bubble sort" generation).
   Each adjacent swap is a 2D `intervalIntegral_swap` applied to two
   consecutive axes after peeling the first `i` integrals via
   `Fin.consEquiv`. This is the same induction that proves
   `Equiv.Perm.sign` factors through adjacent transpositions.

3. **`Measure.pi` and `Measure.prod` agree on `Fin 2`.** Specifically,
   `(Measure.pi (Fin 2 → ?) μ) ≃ μ 0 ⊗ μ 1` via
   `MeasurableEquiv.piFinTwo`. So the S2 `n = 2` reduction lemma
   is essentially a measurable-equivalence-driven `pull-along`
   identity. The parent's 2D Fubini drops in directly.

4. **The `Measure.pi (fun i => μ.restrict (uIcc …))` ↔
   `(Measure.pi μ).restrict (Set.pi univ (fun i => uIcc …))`
   identity is a likely Mathlib gap.** Mathlib has `Measure.pi_pi`
   for the unrestricted product, but the `restrict` analogue
   does not appear in the parent's import set or in any gallery
   proof grep. If unavailable, hand-prove via the generators of
   `Measure.pi` (rectangles `Set.pi univ S` with `S i ⊆ uIcc …`),
   which is ~30 extra lines in S2.

5. **Bochner generalisation is decoupled.** The parent file is
   scalar (`f : ℝ → ℝ → ℝ`). OQ-02 (Bochner) is a separate sibling
   open question. For OQ-04 we keep the scalar target to limit
   S1–S4 scope; an S5+ extension would replace `ℝ` codomain with
   `[NormedAddCommGroup E] [NormedSpace ℝ E]`, which is a uniform
   type-class lift — every helper in the chain
   (`integral_of_le`, `integral_symm`,
   `MeasureTheory.integral_integral_swap`,
   `MeasureTheory.measurePreserving_piCongrLeft`) is already
   Bochner-polymorphic in Mathlib.

### Three Mathlib gaps (candidates for upstream contribution)

A. **`Measure.pi_restrict`**: identity
   `Measure.pi (fun i => μ i |>.restrict (S i))
     = (Measure.pi μ) |>.restrict (Set.pi univ S)`
   for `[∀ i, SigmaFinite (μ i)]`. The `Measure.pi`–`restrict` interaction
   should be a one-line `Measure.ext` + `pi_pi` argument, but no
   gallery proof uses such a lemma — they all hand-coerce.

B. **`MeasureTheory.iteratedIntervalIntegral`** as a Mathlib-level
   `def`. The 1D `intervalIntegral` exists, the n-fold Bochner
   `integral` exists, but the iterated `intervalIntegral` form
   (which is what mathematicians actually write on the page) is
   absent. This OQ-04, once closed, is a candidate Mathlib PR
   targeting `Mathlib.MeasureTheory.Integral.IntervalIntegral`.

C. **`intervalIntegral.integral_comm`** (the OQ-02 / OQ-01-01-02
   parent's natural Mathlib name) is similarly missing. The S2+
   work on OQ-04 should be additive to whatever future PR closes
   the parent — i.e., the n-dim `def` + theorem should be a
   header-level upgrade of the 2D form.
