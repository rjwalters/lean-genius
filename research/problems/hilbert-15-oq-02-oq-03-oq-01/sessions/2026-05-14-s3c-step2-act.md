## Departures from the PREP recipe

### 1. Sigma decomposition uses `simp`-friendly forward-and-back rewrite chain

S3c-prep-5 §4 sketches the decomposition via `card_eq_sum_ones → sum_filter
→ Fintype.sum_sigma → Fin.sum_univ_two`, leaving the re-folding to the ACT
author. The realised proof in `SkewSSYTFin.content_two_eq_rows` (~7 lines)
is:

```lean
  unfold SkewSSYTFin.content
  rw [Finset.card_eq_sum_ones, Finset.sum_filter, Fintype.sum_sigma,
      Fin.sum_univ_two, ← Finset.sum_filter, ← Finset.sum_filter,
      ← Finset.card_eq_sum_ones, ← Finset.card_eq_sum_ones]
```

Forward chain rewrites both `card` sides to the `if … then 1 else 0` form,
splits over `i : Fin 2`, then reverses on both row-0 and row-1 components.

### 2. Row-1 zero-count proved by `omega` not `Nat.add_sub_cancel_left`

S3c-prep-5 §4 closes the row-1 zero-count via
`exact (Nat.add_sub_cancel_left).symm`. The realised proof is:

```lean
  have h := T.content_two_eq_rows 0
  rw [skewSSYTFin_row0_zero_count_of_row0_zero T hrow0, hcont0] at h
  omega
```

`omega` is more robust because the rewrite places `h` in the form
`lam.parts 0 = r₀ + row1_zero_count` and the goal is
`row1_zero_count = lam.parts 0 - r₀`. The truncated-subtraction direction
is closed by `omega` (which proves `lam.parts 0 ≥ r₀` implicitly from `h`),
sidestepping the explicit `h_lam0_ge` invocation that the PREP recipe
threads through. The standalone `skewSSYTFin_lam0_ge_r0_of_row0_zero`
lemma is still added because it's a useful corollary for downstream
Step 5 closure work.

### 3. Row-1 one-count uses the same row-decomposition (not row-size + zero-count)

S3c-prep-5 §3.4 sketches the row-1 one-count via "row 1 has `r₁` cells; if
row1_zero_count is `c₀`, row1_one_count is `r₁ - c₀`". The realised proof
uses the same `content_two_eq_rows` machinery on `k = 1` directly:

```lean
  have h := T.content_two_eq_rows 1
  rw [skewSSYTFin_row0_one_count_zero_of_row0_zero T hrow0, hcont1] at h
  omega
```

Cleaner: avoids the row-size-and-content-equation chain (which would need
two `Partition.weight_two_eq` invocations plus `hsupp`) by exploiting the
direct content equation `T.content 1 = lam.parts 1`.

### 4. `Partition.weight_two_eq` is `@[simp]` and declared in the OQ01 namespace

The adapter lives at `Hilbert15OQ02OQ03OQ01.Partition.weight_two_eq` (full
name), mirroring the convention `Hilbert15OQ02OQ03OQ01.toPartition2_size`.
The `@[simp]` annotation triggers on `p.weight` patterns regardless of
namespace because simp matches on LHS structure.
