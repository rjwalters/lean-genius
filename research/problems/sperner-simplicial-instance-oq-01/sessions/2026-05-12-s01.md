## Four candidate constructions

### Candidate A — Trivial 1-cell triangulation (minimal smoke test)

**Goal.** Smallest possible `Triangulation V 2` instance: a single
2-simplex with three boundary faces, no interior adjacency.

**Choice.** `Cell := Fin 1`; `V := ℕ`; vertex `0 ↦ {0, 1, 2}`;
`adj _ _ = none`.

**Pseudocode.**

```lean
def trivialTriangle : Triangulation ℕ 2 where
  Cell := Fin 1
  cellDecEq := inferInstance
  cellFintype := inferInstance
  vertex _ k := k.val  -- 0 ↦ 0, 1 ↦ 1, 2 ↦ 2
  vertex_injective _ a b hab := by
    fin_cases a <;> fin_cases b <;> simp_all
  adj _ _ := none
  adj_symm := by intros; simp_all
  adj_vertex := by intros; simp_all
  adj_ne := by intros; simp_all
```

**Axiom discharge estimate.** ~25 LOC including docstring (4
trivial axioms via `simp_all` after pattern-matching the `none`
output of `adj`).

**Boundary door count.** For any Sperner coloring `c : ℕ → Fin 3`
with `c 0 = 0`, `c 1 = 1`, `c 2 = 2`: each of the 3 faces `k ∈ Fin 3`
is a boundary face (`adj _ k = none`); the door-property
`IsDoor c trivialTriangle.toCellComplex 0 k` for face `k` excluding
vertex `k` reduces to the parity check on `{c j : j ≠ k}`.

The standard Sperner-coloring `c i := i` gives:
* Face `0` excludes vertex `0` → image `{1, 2}` — needs to be
  panchromatic on `Fin 3` minus `0`, i.e. `= {1, 2}`. **Yes**, it is a door.
* Face `1` excludes vertex `1` → image `{0, 2}` ≠ `{0, 1}`-pattern; the
  exact `IsDoor` condition needs to be inspected once `CellComplex.IsDoor`
  is fetched into context.

**Utility.** Provides the **base case** for the inductive structure
in `boundary_doors_odd` (S2 of this open question family). Establishes
that the trivial instance compiles; **does not** exercise the
`adj_vertex` machinery in a non-trivial way (always `none`).

**Risk.** None — every axiom discharges trivially.

**Estimated LOC.** ~30 (definition + 4 axioms + helper for `vertex_injective`).

**Estimated session time.** ~20–30 min.

### Candidate B — Trivial triangulation with sorted-vertex API (template alignment)

**Goal.** Same as Candidate A but uses the `linearOrder V` machinery
matching the `AbstractSimplicialData` lift framework on lines 700+ of
`SpernerSimplicialInstance.lean`.

**Choice.** `Cell := Fin 1`, `V := Fin 3` (with the implicit
linear order), vertex `0 ↦ id : Fin 3 → Fin 3`.

**Pseudocode.**

```lean
def trivialTriangleSorted : Triangulation (Fin 3) 2 where
  Cell := Fin 1
  cellDecEq := inferInstance
  cellFintype := inferInstance
  vertex _ k := k  -- identity Fin 3 → Fin 3
  vertex_injective _ := Function.injective_id
  adj _ _ := none
  adj_symm := by intros; simp_all
  adj_vertex := by intros; simp_all
  adj_ne := by intros; simp_all
```

**Estimated LOC.** ~20 (the `Function.injective_id` shortcut).

**Estimated session time.** ~15 min.

**Trade-off vs. Candidate A.** Sleeker; doesn't generalize to
non-trivial vertex maps. **Recommended if S2 target is to use the
`AbstractSimplicialData` lift later** (then `Fin 3` as `V` is the
natural choice for the standard simplex).

### Candidate C — m×m subdivision of the unit-2-simplex (Sperner standard)

**Goal.** `Triangulation` for the standard m-refinement of the
unit-2-simplex, with `m²` up-triangles + `(m-1)²` down-triangles
(or equivalently `m² + (m-1)²` total cells in barycentric form,
but for the standard right-triangle layout: `m²` up + `m(m-1)/...`
down depending on convention).  This is the **classical Sperner
demonstration object** — a triangulation of `{(i,j) : i+j ≤ m}`.

**Choice.** Let `V := ℕ × ℕ`; cells indexed by `Fin m × Fin m × Bool`
where the `Bool` distinguishes "up" (vertices `(i,j), (i+1,j), (i,j+1)`)
from "down" (vertices `(i+1,j), (i,j+1), (i+1,j+1)`).  Restricted to
`i + j < m` for up-triangles and `i + j < m - 1` for down-triangles
(or similar — exact predicate depends on the refinement convention).

**Pseudocode (sketch, S2/S3 deliverable, not S1).**

```lean
inductive TriCell (m : ℕ)
  | up   (i j : Fin m) (_ : i.val + j.val < m)
  | down (i j : Fin m) (_ : i.val + j.val + 1 < m)
  deriving DecidableEq, Fintype

def triVtx (m : ℕ) (c : TriCell m) (k : Fin 3) : ℕ × ℕ := match c, k with
  | TriCell.up i j _, ⟨0, _⟩ => (i.val, j.val)
  | TriCell.up i j _, ⟨1, _⟩ => (i.val + 1, j.val)
  | TriCell.up i j _, ⟨2, _⟩ => (i.val, j.val + 1)
  | TriCell.down i j _, ⟨0, _⟩ => (i.val + 1, j.val)
  | TriCell.down i j _, ⟨1, _⟩ => (i.val, j.val + 1)
  | TriCell.down i j _, ⟨2, _⟩ => (i.val + 1, j.val + 1)

def triAdj (m : ℕ) (c : TriCell m) (k : Fin 3) :
    Option (TriCell m × Fin 3) := ... -- 6 cases per Bool × k.val
```

**Axiom discharge.** Each of the 4 axioms requires
~m²-independent case analysis:
* `vertex_injective`: case-split on `(c, k)`, `simp` + `omega`.
* `adj_symm`: 6 cases for up→down and 6 for down→up (each pair
  contributes 1 symmetry obligation).
* `adj_vertex`: 12 cases of "shared edge image equals".
* `adj_ne`: 12 cases of "neighboring cell ≠ self".

**Estimated LOC.** ~250–400 for full discharge.

**Estimated session time.** ~3–6 hours over multiple sessions.

**Boundary door count.** This is where it gets interesting. The
3 boundary faces of the unit-2-simplex are
* `j = 0` (bottom edge): vertices `(i, 0)` for `i ∈ {0,...,m}`.
* `i = 0` (left edge): vertices `(0, j)` for `j ∈ {0,...,m}`.
* `i + j = m` (hypotenuse): vertices `(i, m-i)` for `i ∈ {0,...,m}`.

The Sperner coloring `c (i,j) ∈ Fin 3` with boundary conditions
`c (i,0) ∈ {0,1}`, `c (0,j) ∈ {0,2}`, `c (i,m-i) ∈ {1,2}` (or
similar 3-color boundary scheme) ought to yield an odd number of
boundary doors via the 1-d Sperner lemma applied to each edge.

This is the **main attraction** of the open question: it would
exercise `boundary_doors_odd`'s decomposition hypotheses
non-trivially via three independent 1-d Sperner applications on
the three boundary edges. The `interval_sperner` lemma at line 982
gives the 1-d ingredient.

**Utility.** Highest. Demonstrates the full Sperner pipeline on
the canonical example. Sets up the n-d generalization (open
question #3 in `meta.json`'s `openQuestions`).

**Risk.** Manageable if approached incrementally:
1. Define `TriCell`, `triVtx` (S2 ACT — ~80 LOC, 0 sorries).
2. Add `vertex_injective` (S3 — ~20 LOC, 0 sorries).
3. Define `triAdj` (S4 — ~60 LOC, definitional).
4. Discharge `adj_ne`, `adj_symm`, `adj_vertex` (S5–S7 — each
   ~50–100 LOC).
5. Wrap into `triangleTriangulation : Triangulation (ℕ × ℕ) 2`
   (S8 — ~10 LOC).
6. (Beyond S1's scope) Demonstrate `boundary_doors_odd` for a
   concrete coloring (S9–S10 — ~150 LOC).

### Candidate D — Freudenthal n-cube triangulation (general dim)

**Goal.** The classical Freudenthal triangulation of `[0,1]^n` via
permutation-paths, restricted to `n = 2`.  Generalizes immediately
to higher dimensions but requires more setup.

**Choice.** Cells indexed by `Sym n × Equiv.Perm (Fin n)`, vertex
maps via cumulative sums; for `n = 2`, this collapses to a 2-cell
unit square (one up-triangle, one down-triangle), which is **not**
the standard 2-simplex triangulation — it's a square.

**Verdict.** Wrong shape (gives a cube triangulation, not a simplex
triangulation). **Reject** for this open question; would be the
basis for a sibling open question.
