### Insertion (file lines 1504-1517)

```lean
  -- B1 fix per S11c §4.4: pick ε so Metric.ball k ε ⊆ s. Then the
  -- parametric-integral lemma's first arg `0 < ε` is matched, and the
  -- ∀-over-ball hypotheses are lifted from the existing ∀-over-s ones.
  set ε : ℝ := min (M - k) (k + M) with hε_def
  have hε_pos : 0 < ε := by
    simp only [hε_def]
    exact lt_min (by linarith) (by linarith)
  have h_ball_eq_s : Metric.ball k ε ⊆ s := by
    intro x hx
    rw [Metric.mem_ball, Real.dist_eq, abs_lt] at hx
    obtain ⟨hx_low, hx_hi⟩ := hx
    have hε_le_Mk : ε ≤ M - k := by simp only [hε_def]; exact min_le_left _ _
    have hε_le_kM : ε ≤ k + M := by simp only [hε_def]; exact min_le_right _ _
    exact ⟨by linarith, by linarith⟩
```

**Rationale for `ε := min (M - k) (k + M)`** (rather than
`(min k (1-k)) / 2` as in S11c §4.1):
- `M - k > 0` since `M = (k+1)/2 > k` (already proven as `hk_lt_M`).
- `k + M > 0` since `k > 0` and `M > 0` (both proven).
- The min of two positives is positive — `lt_min hk_pos…` does not apply;
  we use `lt_min (by linarith) (by linarith)`.
- This ε keeps the ball inside the existing `s = Ioo (-M) M`, so we can
  reuse all the existing `s`-domain machinery (`h_kappa_sq_le`,
  `h_kappa_sq_lt_one`, the bound infrastructure) via the `h_ball_eq_s`
  lift. No re-derivation needed.

## Why §4.4 minimal-diff (not §4.1 full-rewrite)

S11c §4.5 recommends §4.1 as cleaner. We choose §4.4 because:

1. **Preserves all existing infrastructure.** `s`, `hs_nhds`,
   `h_kappa_sq_le`, `h_kappa_sq_lt_one`, `hM_sq_lt_one`, `hM_nn` are all
   still in scope and reused unchanged. §4.1 would discard them and
   re-derive new `κ²<1` bounds from `ε` alone.
2. **Smaller diff surface.** 16 lines of pure addition + 3 localized
   ∀-rewrites + 1 arg substitution. §4.1 would rewrite the whole
   ε/M-setup block.
3. **Smaller chance of new errors.** Without local Docker verification
   (see Build Status), §4.4's smaller surface is strictly safer.
4. **§4.1 can be done later** as a cleanup PR once §4.4 is GREEN.

## Why Site-1 only (Site-2 deferred)

S13's plan called for **Site-1 (dK_dk fix) AND Site-2 (new dE_dk) in
one PR** (~+89 LOC total). This iteration ships Site-1 only (+16 LOC)
to bound the verification surface. The reasoning:

- Site-2 is a brand-new theorem (~+76 LOC) using a different helper set
  (E-side `integrandE_continuous`, `ellipticE_integrable`, etc.).
- A single combined PR multiplies the chance of an elaboration failure
  cascading and masking the actual error site.
- Once Site-1's `dK_dk` is Docker-verified, Site-2 can mirror the same
  proven §4.4 scaffold with high confidence.

Reasonable trade-off given:
- 17 days of no progress = strong signal that big combined patches are
  not landing.
- Site-1 alone removes the load-bearing F1/F2 from production code (the
  concrete blocker, regardless of Site-2 status).

### Residual elaboration risks (low)

If the patch fails to elaborate, likely sources (in decreasing
probability):

1. **`min_le_left _ _` argument inference.** `min_le_left` has signature
   `(a b : α) → min a b ≤ a` in some Mathlib versions and `min a b ≤ a`
   as an instance method in others. If `_ _` doesn't infer, replace with
   explicit `min_le_left (M - k) (k + M)`.
2. **`abs_lt` rewrite direction.** After `rw [Real.dist_eq]` we have
   `|x - k| < ε`, and `rw [abs_lt]` should give `-ε < x - k ∧ x - k < ε`.
   If it fails, replace with `Real.dist_eq.symm` or explicit
   `abs_sub_lt_iff` / `Real.abs_lt_iff` rewrites.
3. **`Metric.mem_ball` direction.** `Metric.mem_ball` should rewrite
   `x ∈ Metric.ball k ε` to `dist x k < ε`. If the direction differs,
   use `Metric.mem_ball.mp hx` instead.

Each is a one-line fix.
