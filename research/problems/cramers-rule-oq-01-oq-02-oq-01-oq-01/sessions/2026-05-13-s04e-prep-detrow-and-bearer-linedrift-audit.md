## 2. Cleaner path via `Matrix.det_eq_sum_mul_adjugate_row`

`Mathlib/LinearAlgebra/Matrix/Adjugate.lean` line 401 (pinned):

```lean
theorem det_eq_sum_mul_adjugate_row (A : Matrix n n α) (i : n) :
    det A = ∑ j : n, A i j * adjugate A j i := by
  haveI : Nonempty n := ⟨i⟩
  obtain ⟨n', hn'⟩ := Nat.exists_eq_succ_of_ne_zero (Fintype.card_ne_zero : Fintype.card n ≠ 0)
  obtain ⟨e⟩ := Fintype.truncEquivFinOfCardEq hn'
  let A' := reindex e e A
  ...
  rw [det_succ_row A' (e i)]
  simp_rw [mul_assoc, mul_left_comm _ (A' _ _), ← adjugate_fin_succ_eq_det_submatrix]
```

This Mathlib theorem **bakes the cofactor sign into the adjugate term**, so the user sees only `A i j * adjugate A j i` (no explicit `(-1)^(i+j)` factor on the LHS). The signs live inside `adjugate A j i` and unfold to `(-1)^(i+j) * det(A.submatrix i.succAbove j.succAbove)` via `adjugate_fin_succ_eq_det_submatrix` on demand.

### 2.1 Proof sketch for `qdetN_step_eq_qdetF` using row-adjugate expansion

Let `M := minorIJ A i j = A.submatrix i.succAbove j.succAbove`.

**Step 1 — `M⁻¹` shape.** By `Matrix.inv_def` (line 167) and `Ring.inverse_eq_inv` (line 374, in a field):
```
(M⁻¹) q p  =  (M.det)⁻¹ * adjugate M q p.
```

**Step 2 — `qdetN_step` expansion.** Unfolding the `qdetN_step` definition (Lean file lines 229–233):
```
qdetN_step A i j M⁻¹  =  A i j - ∑ p, ∑ q, A i (j.succAbove q) * (M⁻¹) q p * A (i.succAbove p) j
                       =  A i j - (M.det)⁻¹ * ∑ p, ∑ q,
                           A i (j.succAbove q) * adjugate M q p * A (i.succAbove p) j.
```

**Step 3 — Recognize the inner sum.** We claim:
```
∑ p, ∑ q, A i (j.succAbove q) * adjugate M q p * A (i.succAbove p) j  =  - (-1)^(i+j) * (adjugate A) j i  +  A i j * M.det * ((-1)^(2(i+j)) - 1)
```

(Wait — this is messy. Cleaner: see §2.2.)

### 2.2 Cleaner derivation through `det_eq_sum_mul_adjugate_row` applied to `A`

By `det_eq_sum_mul_adjugate_row A i` (line 401):
```
A.det  =  ∑ k : Fin (n+1), A i k * adjugate A k i.
```

Split the sum at `k = j`:
```
A.det  =  A i j * adjugate A j i  +  ∑_{k ≠ j} A i k * adjugate A k i.            (*)
```

**Sub-claim (i).** `adjugate A j i = (-1)^(i+j) * M.det`.

*Proof.* By `adjugate_fin_succ_eq_det_submatrix` (line 360):
```
adjugate A j i  =  (-1)^(i + j : ℕ) * det(A.submatrix i.succAbove j.succAbove)
                =  (-1)^(i+j) * M.det.    ✓
```
(Note Mathlib's statement gives the exponent as `(j + i : ℕ)`; commutativity of addition makes this the same as `(i + j : ℕ)`. A single `Nat.add_comm` rewrite ferries between forms — or use `pow_add` to absorb the comm.)

**Sub-claim (ii).** The `k ≠ j` sum reindexes via `Fin.sum_univ_succAbove` (line 68 parent, line 66 `@[to_additive]`) with pivot `j`:
```
∑_{k ≠ j} A i k * adjugate A k i  =  ∑ q : Fin n, A i (j.succAbove q) * adjugate A (j.succAbove q) i.            (**)
```

**Sub-claim (iii).** For each `q`, expanding `adjugate A (j.succAbove q) i` via `adjugate_fin_succ_eq_det_submatrix`:
```
adjugate A (j.succAbove q) i  =  (-1)^(i + j.succAbove q : ℕ) * det(A.submatrix i.succAbove (j.succAbove q).succAbove).
```

The submatrix `A.submatrix i.succAbove (j.succAbove q).succAbove` skips row `i` and column `j.succAbove q`. Applying `det_eq_sum_mul_adjugate_col` (line 413) to this submatrix along its column-`(q'')`-for-the-right-q'' gives, after the sub-Laplace expansion, the formula
```
det(A.submatrix i.succAbove (j.succAbove q).succAbove)
  =  ∑ p : Fin n, A (i.succAbove p) j * adjugate (M with column-q-skipped) p (?)
```

Here the index `(?)` is determined by how the column `j` of `A` appears in the submatrix. **At this point the sign-tracking becomes delicate** — but it is essentially the same calculation as PR #18563 §2 (the "cofactor_chain" step), now using `adjugate` accessors instead of raw `det_succ_row`. The advantage: the iterative Laplace via `det_eq_sum_mul_adjugate_col` and `_row` keeps signs *inside* adjugate notation, deferring sign collection to the final `adjugate_fin_succ_eq_det_submatrix` unfolds.

**Sub-claim (iv).** Combining (i)–(iii) into (*) and re-organising:
```
A.det  =  A i j * (-1)^(i+j) * M.det  +  (stuff involving inner adjugate sums).
```

Now the "stuff" matches `(-1)^(i+j) * (M.det) * (qdetN_step A i j M⁻¹ - A i j)` after the signs collect (the `(-1)^(i+j)` outside on the LHS and the unfolds via `adjugate_fin_succ_eq_det_submatrix` for the inner products combine to give `(-1)^(p+q)` on each term, matching `qdetN_step`'s formula).

Multiplying through by `(-1)^(i+j)` and dividing by `M.det` yields:
```
(-1)^(i+j) * A.det / M.det  =  A i j  -  (M.det)⁻¹ * ∑_p ∑_q A i (j.succAbove q) * adjugate M q p * A (i.succAbove p) j
                              =  qdetN_step A i j M⁻¹.
```

i.e. `qdetN_step A i j M⁻¹ = (-1)^(i+j) * qdetF A i j`. ✓

### 2.3 What's actually different from S4d PREP §2

S4d PREP §2 used `Matrix.det_succ_row` directly, requiring **manual extraction of the `(-1)^(i+k)` exponent** on each summand, then re-organising via `Nat.add_comm` and `pow_add`. This PREP's §2.2 uses `Matrix.det_eq_sum_mul_adjugate_row` to **bake the sign into adjugate notation**, deferring sign extraction. The conceptual benefit is one less explicit `(-1)^?` factor flying around mid-proof.

The actual sign-tracking arithmetic is the same — there's no free lunch. But the Lean proof reads more linearly: each `adjugate_apply` / `adjugate_fin_succ_eq_det_submatrix` unfold appears at a single line of the proof, rather than being interleaved with `det_succ_row` index manipulations.

## 5. Observation: Mathlib's `det_succ_row` internally uses `Fin.cycleRange`

The proof of `Matrix.det_succ_row` at pinned line 769 (`Mathlib/LinearAlgebra/Matrix/Determinant/Basic.lean`):

```lean
theorem det_succ_row {n : ℕ} (A : Matrix (Fin n.succ) (Fin n.succ) R) (i : Fin n.succ) :
    det A =
      ∑ j : Fin n.succ, (-1) ^ (i + j : ℕ) * A i j * det (A.submatrix i.succAbove j.succAbove) := by
  simp_rw [pow_add, mul_assoc, ← mul_sum]
  have : det A = (-1 : R) ^ (i : ℕ) * (Perm.sign i.cycleRange⁻¹) * det A := by
    calc
      det A = ↑((-1 : ℤˣ) ^ (i : ℕ) * (-1 : ℤˣ) ^ (i : ℕ) : ℤˣ) * det A := by simp
      _ = (-1 : R) ^ (i : ℕ) * (Perm.sign i.cycleRange⁻¹) * det A := by simp [-Int.units_mul_self]
  rw [this, mul_assoc]
  congr
  rw [← det_permute, det_succ_row_zero]
  refine Finset.sum_congr rfl fun j _ => ?_
  rw [mul_assoc, Matrix.submatrix_apply, submatrix_submatrix, id_comp, Function.comp_def, id]
  congr 3
  · rw [Equiv.Perm.inv_def, Fin.cycleRange_symm_zero]
  · ext i' j'
    rw [Equiv.Perm.inv_def, Matrix.submatrix_apply, Matrix.submatrix_apply,
      Fin.cycleRange_symm_succ]
```

**Mathlib uses `Fin.cycleRange_symm_zero` and `Fin.cycleRange_symm_succ` to lift `det_succ_row_zero` (Laplace at row 0) to `det_succ_row` (Laplace at arbitrary row `i`).**

**Implication for the S4 ACT path choice (revisiting S4d PREP §5):**

- **Cycle-range/blockReindex path of PR #18409**: re-derives the `i.cycleRange⁻¹ ⊕ j.cycleRange⁻¹` block-reshape at the S4 ACT level. This is the same machinery Mathlib already uses internally to prove `det_succ_row`. The S4 ACT would be re-implementing Mathlib's internal lemma chain at the gallery level.

- **Direct-adjugate path of PR #18563 / row-expansion path of this PREP §2**: calls `det_succ_row` (or `det_eq_sum_mul_adjugate_row`) as a black-box bearer. Mathlib's internal `cycleRange` machinery does the heavy lifting once; the S4 ACT reuses it.

**Maintainability argument.** If Mathlib refactors the `det_succ_row` proof (e.g., switches from `cycleRange` to a different permutation primitive, or absorbs the helper lemmas into a tactic), the **non-cycleRange paths break only at the boundary** (need a new bearer name), while the **cycleRange path breaks throughout** (entire intermediate machinery may need re-deriving). This favors the non-cycleRange paths for long-term maintenance under Mathlib drift.

**Caveat.** If a future Mathlib drift renames `det_succ_row` or changes its signature, both paths suffer. But the rename/signature change is a one-line fix on the non-cycleRange paths and a multi-line refactor on the cycleRange path.
