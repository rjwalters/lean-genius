# Exact singleton-row shortcut for the reviewed residual API

Assume the validated H/E/S-complete a7 preconditions of accepted 2109. Let A(s) be a singleton's empty hosts and T(s) its already assigned singleton neighbors. A single-empty singleton has three singleton neighbors, hence four uncovered high colours and two missing pair neighbors. Its candidate rows are the three perfect matchings of those four colours. A double-empty singleton has one singleton neighbor, six uncovered colours and three missing pair neighbors, hence fifteen matchings. There are seven single-empty and seven double-empty vertices, so at most126 candidate row tests per graph.

For a candidate matching, the selected pair vertices' high supports partition the uncovered colours. Their existing high-neighbor sets are therefore disjoint, and do not meet the high colours of T(s). A selected pair's empty host must avoid B(s)=N_F(A(s)) union the empty hosts of T(s). The selected pairs with an empty host must also have distinct hosts. Pairs without an empty host impose no host restriction and may all have the sentinel zero.

These are precisely the star C4 constraints: intersections between a new pair neighbor and an existing empty neighbor give N_F(A(s)); intersections with an existing singleton neighbor give its high colour or empty hosts; the former is handled by support partition. The existing high neighbor contributes no intersection. Two selected pair neighbors have disjoint high supports, so only a repeated empty host can create their common neighbor. Thus the shortcut returns exactly the singleton portion of the complete residual-row API, not merely a relaxation.
